**Fanimate 0.5.1** lets you run plugins from inside the app, paint pixels on raster layers (with a Paint Bucket that stays inside a line), see and change every colour in a project, turn the canvas, and keep a smaller game file, and it tightens the new 0.5.0 features: keyboard shortcuts, right-click menus, manual chapters and a lot of hostile-input testing. It is still a closed alpha: keep backups, and please [report what goes wrong](https://github.com/toonittmedia/fanimate/issues).

Fanimate 0.5.0 offers this update itself. The installers are **not code-signed yet**: on Windows choose *More info > Run anyway*; on macOS right-click Fanimate, choose *Open*, then *Open* again. `SHA256SUMS.txt` lists checksums for every file.

The project file format is still version 7: projects from 0.5.0 open as they were. Raster layers are ordinary groups of picture layers, so a reader that does not know them still shows the painting, and a saved style may now carry an optional brush hardness that older readers ignore.

## What this release is not

Phase 2 is **not finished**. Still to come: the full brush engine (textures, smudge, brush files), colour marks, the node graph, symbols and the Library, running plugins' own panels and commands, and the AI models beyond the three classical helpers. This release lists only what is built.

## New in this release

### Plugins from inside Fanimate

- **Window > Plugins** lists the plugins in your plugins folder (Open Plugins Folder takes you there). Choose one and Fanimate asks first, in words, what it wants to do to the project: read it, change it. **Run** runs it once, **Always allow and run** remembers that exact plugin version and permission list (a new version, or a plugin that asks for more, asks again).
- A plugin is a program, and **Fanimate limits what it does to your project, not to your computer**. The prompt says so: run only plugins you trust.
- **Everything a plugin does is one undo step**, however many calls it made, and **Window > Plugins > Stop Plugin** ends it. A plugin that runs from the app cannot save the project: use File > Save when it has finished.
- A plugin can declare **commands** in its manifest: it becomes a submenu of Window > Plugins with an entry for each, and the plugin is told which one was chosen in `FANIMATE_COMMAND`. They also show in the command palette (type "plugin"). One "Always allow" covers all of a plugin's commands. `fanimate-cli plugin run --command ID` does the same from a terminal.
- Make one with `fanimate-cli plugin new`; see [Plugins](https://github.com/toonittmedia/fanimate/blob/main/docs/plugins.md).

### Rotate Canvas

- **View > Rotate Canvas**, or **Ctrl+Alt+Left** and **Ctrl+Alt+Right**, turns the view 15 degrees; **Shift + middle-drag** turns it freely. **Ctrl+Shift+0**, or a click on the angle in the status bar, turns it upright.
- Only how you look at the animation turns. The artwork and what is saved are not changed, and drawing, selecting and the transform handles work as usual. The grid turns with the view. While it is turned the rulers are off (the angle shows in their corner) and guides are shown but cannot be moved.

### Painting with pixels, and a project palette

- **New Raster Layer** makes a layer you paint on with the Brush and the Eraser (size, hardness, pen pressure). Pixels are stored as small PNG tiles, only where you painted, so an empty page costs nothing. Scripts can use `add_raster_layer` and `paint`.
- **Flow and Spacing** in the Style panel shape the raster brush: a low flow builds colour up as you go over it again, and the spacing sets how far apart the dabs fall. Scripts can pass `spacing` to `paint`.
- **The Paint Bucket on a raster layer** floods the area you click up to the lines around it and the edge of the page, and covers the soft edge of the line behind it so no pale halo is left. One click is one undo step. Small breaks in an outline (up to about 6 pixels) do not let the fill out; a wider one does. Style > Bucket tolerance and Bucket gap change that. Scripts can use `fill`, with an optional `gap`.
- **The Eyedropper on a raster layer** picks the colour of the painted pixel you click.
- **Saved styles remember the brush's hardness**, so a soft airbrush and a hard pen can be two styles. Styles you saved before keep working and leave the hardness as it is. Projects from 0.5.0 open as they were.
- **Style > Palette** lists every colour your artwork uses and how many paints show it. Change a swatch and every fill, stroke and colour key with that colour changes at once, in one undo step. Scripts can use `palette` and `replace_colour`. Text and pictures are not recoloured.

### Taking paint layers to other programs

- **File > Export Paint Layers (OpenRaster)…** writes your raster layers and picture layers (as they are on the frame at the playhead) as an `.ora` file for Krita, MyPaint, GIMP and others, with each layer's place, opacity and visibility. Raster layers are trimmed to their paint; nothing is re-drawn. Vector shapes, text, bones, drawings and turned or scaled layers are not written, and the status bar counts them. From a terminal: `fanimate-cli export scene.fnm -o scene.ora --frame 12`.

### Bake expression in the Graph panel

- Under the property buttons, **Bake expression** takes a formula such as `value + 10 * sin(frame / 3)` and a range of frames and writes the answers as keys, in one undo step (nothing is written if any frame fails). Until now this was only available to scripts. See the manual's graph editor section.

### AI models: the rules are in place, no model ships yet

- **Preferences > AI models** installs a model from a file, lists and removes them. Fanimate checks each one against the licence and provenance policy (permissive licences only, documented training data) and its signature before it is installed, and again before it loads; nothing loads while AI is switched off. No model is bundled or downloaded and the engine that would run one is not built yet, so this changes nothing you can do today. `fanimate-cli models` does the same from a terminal.

### Smaller game files, and what a file would cost

- `fanimate-cli export scene.fnm -o scene.fnmr --tolerance 2` leaves out keys the game would not miss (the tolerance is how far, in document units, any point may be drawn from the exact frame). A straight move is two keys; a rig that swings its limbs through big angles keeps most of its keys, because a turn is not linear. The file is an ordinary version 1 file, so every runtime reads it.
- `--estimate` on a Lottie or runtime export says how big the file would be and how many keys it has, and writes nothing.

### Shortcuts and menus for the 0.5.0 helpers

- Clean Up Lines **Ctrl+Alt+L**, Suggest Inbetween **Ctrl+Alt+I**, Auto-Rig Character **Ctrl+Alt+R** and Offset Path **Ctrl+Alt+O**, in both keyboard sets. **Assist** is now in the right-click menu of layers, on the canvas and in the Layers panel, as well as in the Edit menu.
- A new manual chapter ([helpers that need no AI](https://github.com/toonittmedia/fanimate/blob/main/docs/manual/README.md#6b-helpers-that-need-no-ai), poses, canvas rotation, plugins) and the new export routes in the Exporting chapter.

### Harder to break

- The scripting call table is fuzzed: every call is made with its own parameters mangled in the ways a script or plugin could (wrong types, huge, negative and non-finite numbers, deep nesting, missing and extra keys), a call that fails must change nothing, and a client without the edit permission must change nothing through any call. Every exporter (animated SVG, runtime file, Lottie, OpenTimelineIO, one frame as SVG) is tried on projects with zero, negative and non-numeric frame rates and sizes, backwards and enormous ranges, and shapes with damaged points: each makes a clean file or says why not. No panics were found, and these tests now keep it that way.

### For people who test Fanimate

- `FANIMATE_DATA_DIR` makes a copy of Fanimate keep its settings, crash reports, recovery files, pose library and plugin permissions in another folder, so a test copy never touches the real ones.

## Known limits

- Rotating the canvas does not yet keep the angle in the project, and guides cannot be dragged from a turned ruler.
- A plugin run from the app has no panels or menu items of its own yet.
- The Offset distance and the Clean Up tolerance are settings of the editor, not saved in the project.
