**Fanimate 0.4.0** is the first release of Phase 2. It adds animated text, captions, and a scripting interface that programs and plugins can drive, and it fixes the project file format at version 7 as the base for extensions. It is still a closed alpha: keep backups, and please [report what goes wrong](https://github.com/toonittmedia/fanimate/issues).

## The file format moves to version 7

Fanimate 0.4.0 opens every project from earlier versions and saves new ones as **version 7**. **Earlier versions of Fanimate cannot open version 7 projects** (they say the file is from a newer version), so keep a copy of anything you still need to open in 0.3.x. Version 7 adds, all described in [the format specification](https://github.com/toonittmedia/fanimate/blob/main/docs/spec/fnm.md):

- a **`requires` list** in the manifest, so a program that does not know a feature a project needs says so by name instead of silently dropping it;
- a **provenance record** on a layer, saying what tool made its content;
- **bone ids** that never change when bones are reordered or reparented;
- **eased and curved keys** (ease in and out, overshoot, bounce, elastic, custom Bezier curves);
- **text layers** with animators.

The format is meant to stay put from here: later changes add features through `requires` and migrations, and files from every released version keep opening.

## New in this release

### Text

- **Layer > New Text Layer** puts words on the canvas; the Properties panel sets the font (Inter and JetBrains Mono are built in), size, weight, letter spacing, line height, alignment, direction, wrapping, colour and outline. Text is shaped with the font's own ligatures and kerning, reordered for right-to-left text, and wrapped by the Unicode rules. It is drawn as shapes, so it moves, scales and fades like any layer and exports like any other.
- **Text animators** act on a character, word or line at a time, with a range, a selection shape, a soft edge and an optional random order. They move, turn, scale, fade and tint, and every value has keys. Ready-made ones: fade in, typewriter, rise in, pop in and wave.
- **Text on a path:** select a text layer and a layer with a shape and choose *Set Text Path from Shape*. The letters stand on the shape; a closed shape carries the text round; the start along the path has keys.
- **Convert Text to Shapes** turns text into drawing you can edit point by point.
- **Master controllers:** sliders and pads on a bone layer whose values (with keys) play actions, so one control can pose a whole face or body. Make them in the Actions panel (New Slider, New Pad, then right-click a controller and choose Play Action) or from scripts. Projects that use them require `controllers@1`.
- **Secondary motion:** a bone can follow its keys on a spring, thrown by the bones above it, with gravity and wind, and the swing is baked to ordinary keys.
- **Pose library:** save the whole rig as a pose, mirror it left to right by the bones' names, and put it back with Insert Action.
- **Copy to Rig:** right-click an action in the Actions panel and choose Copy to Rig to use it on another character. Bones are paired by name ("arm L", "Arm_L" and "arm.l" are one bone) and each keeps its turn away from its own rest angle, so a walk made on a tall rig plays on a short one. The status bar says how many bones had no match.
- **Controllers in the panel:** the Actions panel lists a rig's controllers with a slider or a square pad each; rename one, link it to actions with Play Action, and set the range each action plays over.
- **SVG import brings text in as text layers** (with its font, size, colour, alignment and position) instead of dropping it.
- **Arabic, Hebrew, Devanagari and Thai** are bundled (Noto Sans, SIL Open Font License) and used automatically for those letters, so a title can mix scripts. Native speakers have not reviewed the shaping yet.

### Captions

- **File > Import Captions** (or drop an `.srt` or `.vtt` file on the window) reads subtitles into a layer of ordinary text layers shown at their times. **Export Captions** writes them back as SubRip or WebVTT.

### Export for the web and games

- **File > Export for Web and Games** adds **Export Frame as SVG**, **Export as Lottie** (a `.lottie` or Lottie JSON that web and phone players read) and **Export Sprite Sheet** (a trimmed, packed PNG and a JSON atlas). Each tells you what it could not carry: pictures are left out, a brush stroke's width changes are drawn evenly, and see-through shapes blend in another colour space, so they can differ slightly from the canvas. The Lottie is baked frame by frame, so it matches the canvas but keeps no bones or easing. On the command line: `fanimate-cli render scene.fnm -o frame.svg`, `fanimate-cli export scene.fnm -o scene.lottie` and `fanimate-cli sheet scene.fnm -o sheet.png --clips walk=1-24`.
- A Character rig exported to Lottie was played in the open-source lottie-web player and matched the canvas (mean error 0.4 of 255).

### Graph editor

- **Window > Graph** draws the keys of the selected layer as curves: drag a key in time and value, right-click for the interpolation choices, and choose **Custom curve** to reshape the motion with two handles. The scripting API has `curves`, `move_key` and `set_key_interpolation`.

### Simple mode

- **Window > Workspace > Simple** shows only the basic tools, Layers, Properties, Style and the timeline, for a first hour with Fanimate. Any other workspace brings the rest back.

### Easing

- Keys can ease in and out, overshoot, bounce, overshoot back, spring elastically, or follow a Bezier curve, besides step, linear and smooth.

### Scripting

- **`fanimate-cli script`** runs Fanimate with no window and answers JSON-RPC 2.0 requests, one per line, on standard input and output. A script in any language starts it as a child process. It can open or create a project, add layers, shapes, text and captions, move and key layers, set the project's size and rate, undo and redo, and save; every call is one undo step. `api.methods` lists what a build offers. See [docs/scripting.md](https://github.com/toonittmedia/fanimate/blob/main/docs/scripting.md), which has a Python example.
- The calls include `curves`, `move_key` and `set_key_interpolation` for the graph editor, `retarget_action` for Copy to Rig, and the controller calls (`add_controller`, `link_controller`, `rename_controller` and more).
- The interface is the Rust crate `fanimate-api`, and its public surface is recorded in a file that a test checks, so changes to it are always visible. It is labelled **0.1.0-unstable**: names and shapes may still change before 1.0, and the plan is to freeze it at 1.0.

### Other

- **Work offline** in Preferences, and policy files (`fanimate-policy.json` beside the program, `policy.json` in your settings folder) that let an organisation switch off network, AI and cloud features. Today only the update check uses the network.
- Text, text on a path, captions and the scripting calls are covered by tests, including damaged files and hostile input.

## For contributors

- New crates: `fanimate-text` (shaping and outlines) and `fanimate-api` (the scripting interface). `docs/architecture.md` and `CLAUDE.md` describe the rules that go with them: transactions, required features, API first.
- `fanimate-cli` gained `script`, `serve` and `sheet`; `render` writes `.svg` and `export` writes `.lottie` and `.json` (Lottie); `bench --text N` measures text.
